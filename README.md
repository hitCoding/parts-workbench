# 料格 · 电子物料工作台

本地优先的个人电子物料管理工具。Vue 3 + TypeScript 页面，Python FastAPI 服务，SQLite 持久化。前端构建后由同一个后端提供，日常运行只需一个 Python 服务。

## 启动

已安装 Python、uv 和 Node.js 后，在项目目录运行（首次启动自动安装依赖并构建页面）：

```sh
cd parts-workbench
./run.sh
```

打开 http://127.0.0.1:8765 。macOS 也可双击 `start.command`；关闭终端或按 Ctrl+C 停止服务。首次打开先创建管理员账号，密码至少 10 个字符。已有物料与盒子会保留；不会自动塞入示例。空库首页可选择「载入示例数据」。

如果 8765 已被嘉立创 EDA 连接器等程序占用，可运行 `PARTS_PORT=8767 ./run.sh`，然后打开 http://127.0.0.1:8767 。

换到其他电脑：需要 Python 3.11+、uv；首次构建还需要兼容 Vite 7 的 Node.js（20.19+ / 22.12+）。

```sh
uv sync --frozen
cd frontend
npm ci
npm run build
cd ..
./run.sh
```

如果不使用 uv，可以用 Python 虚拟环境安装 `pyproject.toml` 中列出的依赖，再运行 `python -m uvicorn backend.app:app --host 127.0.0.1 --port 8765`。

## 已实现（含扩展功能）

- 器件档案：类别、完整型号、数值、封装、关键参数、商城编号、备注；编辑、归档与恢复。
- 收纳盒：盒号、区域、固定行列位置；格子视图、器件列表、关键词与类别搜索。
- 库存：一物多处、一格一种；精确、估算、未知数量；入库、领料、盘点、整格移位、零库存清格。
- 导入导出：CSV / TSV / XLS / XLSX（普通物料取第一个工作表），列映射，逐行校验，最多 5000 行；UTF-8 / GB18030 CSV；整批事务提交，不覆盖已有格子。
- 项目 BOM：规范化数值与常见阻容封装，保守参数匹配，人工确认及依据，调整制作板数，合并同料需求，缺料与位置清单。
- 型号匹配：没有命中商城编号时，非阻容感器件按完整型号唯一关联，封装标注差异显示提示；明确提供的类别、参数或数值有冲突仍需核对。Value 与完整型号相同的文本不当作额外参数。
- 商城编号优先：一格支持多个备选编号，逐个比较完整编号。唯一命中即关联，不再要求 EDA 与商城的封装文字一致；类别、数值、参数等资料差异显示提示。多个档案命中时留待选择，找不到编号时不会把其他编号误当成同一商品。已人工确认的关联保留。
- 立创 / 嘉立创 EDA BOM：自动定位标题说明后的表头和明细工作表，读取 Comment、Value、Designator、Quantity、Footprint、Supplier Part；忽略 Manufacturer Part、Manufacturer。保留源表行号、商城编号和原始封装，支持按商城编号查找器件。
- 不贴装与样品：每条 BOM 可选择「库存取料」「不贴装」「外部自备 / 样品」，自备项可记录来源或位置。NC / DNP / 不贴 / 不焊标记默认不贴装，可手动改回；这些设置随备份保留。占用或领料后需先释放占用才能修改。
- 备料位置清单：点击「位置清单」或「下一步：位置清单」，未匹配、缺料或待盘点时先提示，知悉后可继续输出已知位置。按盒号、格子排序，列出型号、位号和本格建议取料数；待处理、自备、不贴装项目一并保留。支持 CSV 和打印 / 保存 PDF。生成清单不占用或扣减库存，已领料项目仅作参考。
- BOM 位置图：项目标题旁或位置清单内点击「打印位置图」，按实际盒格布局高亮本项目建议取料位置，显示本格取料数、BOM 行号与位号，芯片保留完整型号。其他格子淡化，待处理参考位置用虚线框，不贴装和自备项单独列出；同器件多个位置按分配数量标记，不重复取料。支持 A4 横向打印 / 保存 PDF，粗框与文字支持黑白辨识；超过 3 × 8 的盒子按原行列分区，仅输出有相关器件的区段。
- 项目占用与领料：只对选择「库存取料」的行使用精确库存计算可用量；不贴装和自备项不参与占用、扣减或缺料采购建议；占用防止多项目重复分配；整单事务扣减，禁止重复领料；支持释放未领料占用。
- BOM 器件显示：关联下拉框、选中库存和匹配结果保留商品名称；芯片等非阻容感器件同时显示完整型号，包括订单导入后类别为「其他」的芯片，便于区分相同封装与电压的不同型号。
- 项目删除：选中项目，在标题右侧点「删除项目」并确认。删除前自动保存完整快照，清理该项目 BOM、匹配与占用；器件、实物库存和历史流水保留。已占用库存会释放，已领料数量不会退回；关联采购保留为独立记录，备注中保留原项目名称。需要恢复时可在「数据与备份」导入删除前快照，恢复会回退全部业务数据。
- 采购：关联项目或日常补货，待购买、待到货、分批验收、入库、取消；已购买不增加可用库存。
- 立创订单：直接读取商城导出的 XLS / XLSX / CSV，识别商品明细与订单号，预览修改后自动建档、生成待到货记录。采购表显示序号、商品名称及完整型号；短名称去掉包装词，只展示首个分号前的内容。
- 订单二次编辑 / 重新导入：订单卡片点「编辑订单」，或再次上传同一订单文件，检查后点「保存订单更新」。相同订单号、商城编号更新原采购项，保留原验收和库存；新增编号生成待验收项；未出现在新文件中的旧明细保留。订购数量不能小于已经入库数量。商品名称和修改的技术参数同步档案，修改技术参数时占用中的器件需要先释放占用。
- 订单归档：已完成验收（或剩余采购已取消）的订单可点「归档订单」。默认展示「当前订单」，在「已归档」可查看、编辑及恢复订单；归档不删除采购记录，不改变库存和流水，状态保存在 SQLite 中并随备份恢复。修改订单或验收后若产生未完成采购，会自动恢复到当前订单，避免遗漏待验收物料。
- 修改验收：订单卡片或已入库采购行点「修改验收」。可修改累计验收数量、格子，支持分散存放和撤回；按差额调整库存，原流水保留并追加「验收修正」。旧版本订单从原验收流水还原。扣减不能影响已占用库存，原格不足或数量不精确时需先核对实物、盘点或移回原格；修正为零后可重新验收。订单更新和验收修正前均自动备份，整批事务提交，并检测过期页面，防止重复入库或覆盖他人修改。
- 手动入库：新器件建档并入库，或已有器件补货；器件、库存与流水在同一事务中保存，失败时全部回滚。
- 流水：所有库存变更持久化；页面展示最近 300 条，完整历史在数据库中。
- 备份：一致的 SQLite 快照下载，恢复前预览、结构与完整性检查，恢复前自动快照；启动与导入前也自动备份。
- 打印与扫码：盒格二维码标签、器件二维码，摄像头 / 图片识码 / 扫码枪，支持盒号与商城编号定位，可打印为 PDF。
- 图片与附件：器件照片、料袋标签、PDF 数据手册；每个文件 ≤8 MB，每器件最多 12 个，总附件量 ≤150 MB。图片会重新编码以去除元数据。附件保存在 SQLite 中，随备份携带。
- OCR：macOS 使用本机 Apple Vision，Linux 使用本机 Tesseract；识别后校对 CSV，再进行列映射与验证，绝不直接增加库存。
- 账号与权限：首个管理员初始化、管理员 / 编辑者 / 只读成员、账号停用、会话撤销、密码修改与操作审计。
- 数据迁移：自动升级旧 v1 数据库，升级前留快照；可预览、迁移并恢复 v1 / v2 备份。
- 部署：Docker 镜像、Compose、健康检查、Caddy HTTPS 反向代理示例。

## 建议使用流程

1. 新建盒子，例如 `R01`，行列创建后固定，格号自动生成 `A1`、`A2` 等。
2. 新建器件，填好类别、封装和关键参数，在详情「添加存放位置」。或下载物料模板批量导入。
3. 在「项目与 BOM」导入原始 BOM，支持立创 / 嘉立创 EDA 导出的 XLSX / XLS / CSV。自动识别实际明细表头和项目名称；确认列映射，点击「检查并预览」，修复错误后创建项目。Quantity 作为单板用量，制作板数另填。
4. 打开项目或点击「重新自动匹配」一次核对整张 BOM。先按商城编号，再按完整型号、阻容感规格匹配；查看资料差异与未匹配原因，人工确认只在当前项目生效。
5. 可先在提示后输出位置清单找料。不贴装或样品选择对应备料方式；待盘点项先盘点，真正缺料项再添加采购。
6. 已购买后验收入库，再返回项目核料。需要从库存取料的行全部够用后，占用这些器件，再确认领料；不贴装、自备项不会阻止这一步。

### 采购与入库

- **导入立创订单**：进入「采购与入库」，选择「导入立创订单」，上传商城订单详情文件。程序会定位商品表头，跳过订单抬头与空白模板工作表；只提取订单号、商品明细、数量及单价，不导入收货地址、电话或发票信息。文件在本机解析，无需商城 API 或登录凭据。
- 核对型号、封装、类别、参数及订购 / 发货数量。修改后先点「检查修改」，再「确认导入采购订单」。导入只增加器件档案和待到货采购记录，**不会增加库存**；同一订单号再次导入会被拦截，已有商城编号的档案会复用，冲突需先核对。
- **到货验收**：在订单卡点「验收此订单」，勾选本次实际到货项并填写数量、存放格子。可选盒子后「按顺序分配格子」；盒子满时切换另一个盒子继续分配，已经分配的位置会保留。确认验收入库后才增加库存，并记录流水；整批有冲突则全部回滚。发货数量仅用于建议本次数量，仍需核对实物。
- **零散物料**：点击「手动入库」，选择「新器件并入库」或「已有器件补货」，填写数量及格子后保存。一个格子只存一种器件；同种器件可分放多个格子。
- **采购计划**：用于记录尚未购买的器件；下拉框没有器件时可以从「新建器件档案」先建档。不要把计划数量直接当成现货。
- 商城描述中的参数仅作保守提取；缺失的电容介质、无法确定的类别等会提示人工核对，不会根据型号猜测参数。

### 匹配边界

- 支持 `0.1uF = 100nF`、`4K7 = 4.7kΩ` 等标准表达；阻容前缀 `R0603 / C0603 / 0603` 统一。
- 商城编号优先：一格支持多个备选编号，逐个比较完整编号。唯一命中即关联，不再要求 EDA 与商城的封装文字一致；类别、数值、参数等资料差异显示提示。多个档案命中时留待选择，找不到编号时不会把其他编号误当成同一商品。已人工确认的关联保留。
- 没有商城编号或完整型号时，阻容感按类别、数值和封装查找。符合 BOM 已提供参数的候选只有一个时直接匹配；未指定的电阻精度 / 功率、电容耐压 / 介质、电感额定电流会保留提示。多个合格候选、明确参数冲突、类别 / 数值 / 封装不一致仍需人工核对。自动关联不补写 BOM 需求参数，也不会自动领料。
- 立创 BOM 的 `C0603 / R0603 / L1210` 统一为尺寸编号；已识别的封装前缀规范化。源封装文字保留，无需逐个维护商品封装别名；按规格查找替代料时仍要求封装一致。
- BOM 的 Manufacturer Part 和 Manufacturer 两列不参与导入、匹配或冲突判断。Comment 用于需求名称，Value 用于数值，Supplier Part 用于商城编号。位号个数与单板用量不一致时提示人工核对。
- 无商城编号时的参数比较采用保守相等判断，不自动认定更高耐压可以替代。按编号关联表示同一商品，资料有差异时仍应核对 BOM 或器件档案；不会自动补写需求、占用或领料。
- 无编号的芯片必须完整型号唯一，明确参数冲突需核对。未找到档案和冲突字段分别显示原因，NC/DNP 默认不贴装；不会为了清空待匹配数量而随意绑定。当前未集成数据手册或商城自动查询。
- 同一项目重复出现的器件按 BOM 行序分配可用量，不重复计算库存。采购建议按器件汇总，未把在途采购算为库存。
- 已领料的 BOM 不可再次修改或领料；页面会提示当前剩余库存，实际领料结果见流水。
- 不支持多台设备离线分别修改再合并；多端应连接同一个服务。

## 数据与备份

- 主库：`data/inventory.sqlite3`；本地快照：`backups/`。恢复上传上限为 200 MB。
- 可通过 `PARTS_DATA_DIR` 改变主库目录，快照在该目录同级的 `backups/`。
- 下载的 `.sqlite3` 文件包含结构化数据、附件和密码哈希，无外部附件依赖。请妥善保存备份文件。
- 恢复会替换全部当前数据。先预览，再勾选确认；原数据另存 `before-restore-*.sqlite3`，可再次导入恢复。
- 自动快照不会自动清理，可定期将重要备份保存到其他设备，并自行整理旧快照。
- 当前 schema_version 为 2，可恢复 v1 和 v2 备份。恢复只替换业务数据与附件，保留当前账号、会话和操作审计，避免恢复他人的账号权限。新机器先创建管理员，再导入备份。

## 开发与验证

```sh
uv sync --group dev --frozen
uv run pytest -q
cd frontend
npm run build
npm run dev
```

Vite 开发端口默认 5173，API 代理到 8765。开发需另开终端运行后端。修改前端后重新 `npm run build`；修改后端后重启服务。

代码结构：

```text
backend/app.py        API、备份恢复、静态页面入口
backend/domain.py     库存、核料、项目占用与领料规则
backend/db.py         连接、事务、快照
backend/schema.sql    数据表与约束
backend/imports.py    CSV/XLS/XLSX、列映射、导入校验
backend/bom.py        立创 / 嘉立创 EDA BOM 识别、封装规范、源表信息
backend/procurement.py 立创订单解析、采购导入、批量验收、手动入库
frontend/src/         Vue 页面、类型、样式
tests/               核心数据一致性与 HTTP 接口测试
```

## 手机 / NAS

默认仅本机访问。所有业务 API 都需要登录；管理员可创建编辑者和只读成员。首次管理员只能从本机创建，远程初始化需显式配置 `PARTS_SETUP_TOKEN`。局域网 HTTP 可以查找物料、拍照识码与选择二维码图片；手机实时扫码需要 HTTPS。「拍照识码」请求使用后置相机，实际打开相机或文件选择器取决于手机浏览器。

受信任局域网使用时，在服务机器启动（地址改成该机器真实的局域网 IP）：

```sh
PARTS_HOST=0.0.0.0 PARTS_ALLOWED_HOSTS=localhost,127.0.0.1,192.168.1.10 ./run.sh
```

手机打开 `http://192.168.1.10:8765`。所有操作通过后端读写同一份 SQLite，数据库文件应保存在服务机器本地磁盘，勿通过 SMB 共享文件让多台机器直接写库。公开部署请使用 HTTPS 反向代理，按下方配置主机白名单和安全 Cookie。

批量验收时，分配盒子默认选项为「自动按类别分配（根据盒名）」。勾选到货项后点击「按类别分配格子」，按器件类别匹配名称包含该类别的盒子（例如“贴片电阻”“贴片电容”），优先已有同器件的精确库存格，再按盒号、行列顺序使用空格。已选位置保留；没有对应分类盒子或可用格子时逐项提示，可手动指定。选择具体盒子后仍可按顺序分配，不受名称分类限制。分配仅填写建议位置，确认验收后才增加库存。

## 扩展功能使用

- **扫码**：「扫码与协作」中输入 `R01 / A1`，使用扫码枪，点击「拍照识码」拍照后自动识别，或通过「识别码图」选择已有图片；HTTPS 或本机访问还可使用「实时扫码」。器件详情有器件码；「打印当前盒子标签」生成每个格子的二维码。料格码只编码对象标识，不含密码；在工作台扫描即可定位。
- **资料**：打开器件详情，在「图片与资料」上传照片或 PDF。移除前自动生成完整快照，可通过恢复快照找回。
- **OCR**：在「扫码与协作」选择图片，先看识别原文，再编辑 CSV 表格；补齐类别、数量、盒格等字段后进入导入预览。BOM 用途需增加单板用量列并映射。数量、精度、耐压等必须人工核对。
- **成员**：管理员在「扫码与协作」添加成员。编辑者可维护库存和项目；只读成员只能查询、扫码和下载清单。备份、恢复、成员管理、审计仅管理员可用。禁用账号或修改权限会立即撤销该成员已有会话。
- **审计**：记录账号、成功提交的 API 路径与时间，不记录密码或请求内容。具体库存数量仍见库存流水。密码使用 Argon2id 哈希，会话使用 HttpOnly / SameSite Cookie，默认 7 天过期；修改密码后其他会话退出。

macOS 首次 OCR 需要系统 Swift 编译器，已在本机编译验证，产物在忽略目录 `.runtime/`。Linux 可安装 `tesseract-ocr tesseract-ocr-chi-sim`；Docker 镜像已包含。相机需要浏览器权限，图片识码不需要相机。

## Docker / HTTPS 部署

```sh
cp .env.example .env
# 编辑 .env，替换 PARTS_SETUP_TOKEN，不要使用示例口令
# 如需局域网访问，将 PARTS_BIND 改为 0.0.0.0，并补充 PARTS_ALLOWED_HOSTS
# HTTP 下 PARTS_SECURE_COOKIE=0；HTTPS 下设置为 1
docker compose up --build -d
```

数据保存在 `parts-store` 命名卷中的 `/store/data` 和 `/store/backups`。不要执行 `docker compose down -v`，除非已确认需要删除整个卷。首次创建管理员需要 `.env` 中的初始化口令。`.env` 不进入镜像或 Git。

宿主机使用 Caddy 时可参考 `docs/Caddyfile.example`，将真实域名加入 `PARTS_ALLOWED_HOSTS`，设置 `PARTS_SECURE_COOKIE=1`。反向代理只连接本机 8765，浏览器通过 HTTPS 访问。TLS 证书签发与公网部署尚未执行。

Compose 配置已校验；Docker 镜像尚未在本次环境中构建运行，需在目标部署机器验证。

## 需要外部接入的能力与边界

- 商城实时库存、自动数据手册抓取与自动下单尚未接入。需要具体供应商开放 API、凭据和授权；立创订单文件导入、采购记录、供应商名称、链接备注和人工验收已可用，文件导入无需外部 API。
- 不支持各设备断网修改后自动合并。多端连接同一个服务；断网时写入失败，不会伪造成功或排队自动重复领料。
- 账号权限按整个工作台划分，尚无按项目 / 仓库隔离与 SSO。没有定期后台备份调度，已有启动、导入、升级、恢复、删除附件前快照与手动备份。


管理员忘记密码时，可在服务机器本地交互执行 `uv run python -m backend.manage reset-password 用户名`，按提示输入新密码（不会放进命令参数或日志）。这需要服务器文件系统访问权，并会记录审计与撤销原会话。不会自动启用停用账号或提升角色。
